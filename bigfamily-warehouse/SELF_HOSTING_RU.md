# BIGFAMILY — запуск самостоятельного склада

Эта инструкция запускает BIGFAMILY на одном сервере без внешнего PostgreSQL/Supabase. Встроенная PGlite хранит данные на диске сервера.

## Важно до запуска

- Выберите сервер/компьютер, который не выключается, и диск с постоянным хранением.
- Не используйте ephemeral/временный диск хостинга: при его очистке база может исчезнуть.
- Не запускайте два экземпляра приложения одновременно с одной папкой данных.
- Включите HTTPS перед доступом из интернета. Не публикуйте порт приложения напрямую без защищённого прокси.
- GitHub хранит код; складские записи не записываются в GitHub автоматически.

## Установка (Linux/macOS)

1. Установите Node.js 22.x.
2. Склонируйте репозиторий и перейдите в папку проекта:
   `git clone https://github.com/behruzoripov123vip17-ops/bigfamily-warehouse.git`
   `cd bigfamily-warehouse/bigfamily-warehouse`
3. Установите зависимости: `npm ci`.
4. Создайте конфигурацию и пароль владельца: `npm run setup:owner`. Сохраните пароль из вывода в менеджере паролей. Скрипт не перезаписывает существующий `.env.local`.
5. Соберите приложение: `npm run build`.
6. Запустите: `npm start`.
7. Войдите на сервере по адресу `http://localhost:3000` (для интернет-доступа настройте HTTPS-прокси). Логин `owner`, пароль — созданный на шаге 4.

## Постоянное хранение

По умолчанию база находится в `data/postgres`. Чтобы вынести её на отдельный постоянный диск, перед запуском задайте `BIGFAMILY_DATA_DIR` — путь к каталогу базы. Каталог должен быть доступен для записи пользователю, запускающему приложение. Не перемещайте/не удаляйте этот каталог при обновлении.

## Перенос данных из прежнего «Мой склад»

1. В старом браузере откройте свой склад и раздел «Резервная копия».
2. Скачайте JSON-файл.
3. В новом серверном складе откройте «Резервная копия» и восстановите файл **в пустой склад**.
4. Сверьте каталог, остатки и число операций/заказов.

## Резервное копирование

- После важных изменений, а также в конце рабочего дня скачивайте JSON-копию из раздела «Резервная копия».
- Храните копии отдельно от сервера (например, на другом устройстве или в защищённом облачном хранилище); не коммитьте их в репозиторий.
- Перед обновлением кода сначала скачайте JSON-копию.
- Для копирования файлового каталога PGlite остановите приложение, скопируйте весь каталог базы, затем запустите приложение снова. Не копируйте активную базу как обычные файлы.
- Проверьте, что резервный файл действительно скачан и хранится в безопасном месте. Не отправляйте копии, пароли или `.env.local` в чат.

## Обновление кода

1. Скачайте JSON-резервную копию.
2. Остановите приложение.
3. Получите обновления кода (`git pull`).
4. Выполните `npm ci`, затем `npm run build`.
5. Запустите `npm start`.
6. Проверьте вход, каталог, журнал, отчёты и резервную копию.

## Ограничения

- Это единый склад владельца; управление ролями сотрудников не предусмотрено.
- Для нескольких процессов/серверов, работающих с одной базой, используйте внешний PostgreSQL, а не одну локальную PGlite-папку.
- Резервные копии содержат рабочие данные. Считайте их конфиденциальными.


## Запуск через Docker Compose

В репозитории есть `Dockerfile` и `compose.yaml`. Этот вариант удобен для сервера с Docker Engine и Compose plugin.

1. Перейдите в каталог `bigfamily-warehouse`, где находится `compose.yaml`.
2. Создайте защищённую конфигурацию владельца командой `npm run setup:owner`. Скрипт создаст `.env.local` с сильным случайным паролем. Сохраните пароль из вывода в менеджере паролей. Compose читает именно этот файл. Не добавляйте `.env.local` в Git.
3. Соберите и запустите контейнер:
   `docker compose up -d --build`
5. Контейнер слушает только `127.0.0.1:3000`. Для удалённого доступа настройте на сервере обратный прокси с HTTPS (например, Caddy или Nginx), направив его на `127.0.0.1:3000`. Не открывайте порт 3000 в интернет.
6. Просмотр журнала: `docker compose logs -f bigfamily`. Остановка: `docker compose down`. Обычная команда `docker compose down` сохраняет именованный том с данными; **не используйте** `docker compose down -v`, если не хотите удалить базу.

Данные PGlite находятся в именованном Docker volume `bigfamily_data`, смонтированном в `/app/data`. Обновляйте контейнер только после экспорта JSON-копии. При переносе на другой сервер отдельно перенесите volume или восстановите JSON-копию в пустой склад. Не удаляйте volume при обновлении образа.
