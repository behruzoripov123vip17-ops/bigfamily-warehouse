# BIGFAMILY · склад Wildberries / Ozon

Рабочий кабинет владельца: **сводка**, **каталог одежды**, **приход / расход вещей**, **заказы покупателей**, **ежедневные отчёты и печать**. Интерфейс на русском. Остатки считаются из журнала, а не вводятся отдельно.

## Что считает сайт

В каталоге порядок полей: **артикул → размер → цвет → количество → имя товара**. Карточку и начальный остаток вводит владелец. Сочетание артикула, размера и цвета уникально.

| Событие | Куда записать | Эффект |
| --- | --- | --- |
| Поставщик привёз 500 вещей | Приход / расход → Приход | +500 шт. на складе. Если количество уже введено при создании карточки, приход повторять не нужно |
| WB передал 320, а Ozon 180 новых заказов | Заказы покупателей → две записи по маркетплейсам | 500 заказов; склад не меняется |
| Отгрузили или использовали 120 вещей | Приход / расход → Расход | −120 шт. по выбранному артикулу, размеру и цвету |

При нулевом утреннем остатке на вечер **380 шт.** Один заказ может содержать несколько вещей, поэтому система не вычитает количество заказов из количества изделий. Партии заказов вводятся вручную, без подключения к API маркетплейсов. Записывайте только **новые** заказы, не повторяйте общий итог с начала дня.

## Начать работу

Понадобится Node.js 20.19+ (подойдёт актуальный LTS) и npm. Распакуйте архив, откройте терминал в каталоге с `package.json` и выполните:

```sh
npm ci
npm run build
npm start
```

Откройте **http://localhost:3000**. Интернет нужен при установке npm-пакетов; затем приложение, включая шрифты и иллюстрацию, работает без внешних сервисов. Для редактирования сайта — `npm run dev`. Для постоянной работы нужен сервер с постоянным диском; временный адрес предпросмотра таким хостингом не является.

1. Откройте **Каталог товаров → Новая позиция** и заполните артикул, размер, цвет, количество и имя. Если количество больше нуля, выберите Wildberries или Ozon для начального прихода. В каждой новой операции обязателен один из этих двух маркетплейсов.
2. В **Приход / расход** выберите товар, количество, дату и канал. Журнал хранит комментарии; поиск и фильтры работают по всей истории. Повторное нажатие активного фильтра маркетплейса показывает весь журнал. Старые записи не переназначаются: они сохраняются в журнале, общем итоге и резервных копиях.
3. В **Заказы покупателей** укажите день, маркетплейс и количество новых заказов. Ошибочную запись можно отменить, не удаляя её из журнала.
4. В **Отчёты и печать** выберите день в календаре либо из списка недавних дат. Утро, приход, расход и вечер по каждой позиции рассчитываются из базы, в том числе для дней без движения. Заказы показаны отдельным показателем, с разбивкой по WB и Ozon. Открытые вкладки одного браузера обновляются после записи; на разных устройствах общего склада — при возврате во вкладку и примерно раз в 45 секунд, пока она видима.
5. **Печать полного отчёта** открывает системный диалог: выберите принтер или «Сохранить как PDF». На A4 выводятся все позиции и общие итоги, даже если на экране включён фильтр. Для длинной таблицы повторяется шапка на новых страницах. Отчёты рассчитываются по выбранной дате, а не рассылаются фоновым заданием; для неизменяемого экземпляра сохраните PDF после закрытия дня.

## Где информация

- **Мой склад** изначально пуст: в исходном ZIP не было выгрузки базы, товаров, отгрузок или пользовательских изображений. Примеры из подсказок — не восстановленные товары.
- **Демо** — отдельный склад с образцами данных, только для просмотра. Переключение режима не добавляет примеры в ваш каталог.
- По умолчанию используется **PGlite**, локальная PostgreSQL на диске в `data/postgres` (или `BIGFAMILY_DATA_DIR`). В режиме предпросмотра каждый браузер получает отдельный склад. В `localStorage` хранится **ключ доступа**, а не сами записи. После смены браузера, адреса или очистки хранилища нужен экспорт для переноса. Не публикуйте ключ.
- Нажмите **Резервная копия → Скачать JSON-копию**. На телефоне эта команда в меню ☰. Сохраняйте файл на своём устройстве после важных изменений и до закрытия временного предпросмотра.
- **Восстановление** принимает полную JSON-копию формата `bigfamily.inventory`, версия `2` (и старые копии `1`), только в пустой склад. Импорт либо целиком завершается, либо ничего не добавляет. Существующие записи не заменяются. Сохраняются исходные ID, даты, метки времени, каналы, комментарии, архивы и отмены. Версия 2 включает журнал заказов; старая версия 1 восстанавливает товары и движения без создания вымышленных заказов. Технические ключи повторных отправок не переносятся. Не загружайте конфиденциальные рабочие сведения в демонстрационную среду.
- Исходный ZIP и новый ZIP сайта — это **код**, не будущая резервная копия внесённых вами записей. Не удаляйте каталог данных. Резервное копирование самого каталога PGlite делайте при остановленном сервере; активный сервер безопаснее экспортировать в JSON.

## Если нашлась старая база

Сначала сделайте стандартную полную резервную копию PostgreSQL (`pg_dump`) и сохраните её отдельно. Не применяйте миграции к единственному экземпляру старой базы.

Для таблиц `public.products` и `public.movements` из исходного проекта есть `scripts/export-legacy.mjs`. Он открывает одиночную транзакцию **только на чтение** и пишет **новый** файл, не заменяя существующий. Неизвестные колонки останавливают экспорт: их надо переносить отдельно. Другие таблицы базы этот инструмент не экспортирует.

На своём компьютере задайте `LEGACY_DATABASE_URL` для копии базы, предпочтительно с ролью только для чтения, через переменную среды либо локальный `.env`, затем:

```sh
npm run export:legacy -- warehouse-copy.json
```

Не отправляйте пароли, токены или `.env` в чат или Git. Полученный JSON можно восстановить через «Резервная копия» в созданном пустом складе. До дальнейшей работы сравните число товаров, операций и итоговые остатки со старой базой.

## Постоянный склад владельца на своём сервере

Для **единого** склада с телефона и компьютера внешний сервис базы данных не обязателен. На своём сервере в каталоге проекта выполните:

```sh
npm ci
npm run setup:owner
npm run build
npm start
```

`setup:owner` создаст закрытый `.env.local` с сильным случайным паролем и покажет его один раз в терминале. Логин — `owner`. Существующую конфигурацию скрипт **не перезаписывает**. Режим `BIGFAMILY_SHARED=1` + `BIGFAMILY_OWNER_LOCAL=1` использует одну встроенную PostgreSQL (PGlite) на постоянном диске и требует HTTP Basic на страницах и в API. Запускайте **один** процесс приложения на каталог PGlite. Из интернета открывайте сайт только через HTTPS и обратный прокси. Храните пароль и `.env.local` у себя, а папку `data` — на постоянном диске/томе. Источник и пароль не загружаются в облако этим скриптом. Это одна учётная запись владельца, без ролей сотрудников.

Переключение в режим владельца **не объединяет чужие/личные склады**. Чтобы перенести записи из своего прежнего предпросмотра, сначала скачайте его JSON, затем восстановите в пустой склад владельца. В самом предпросмотре сохраняется прежний режим «Мой склад» с доступом по ключу браузера; демо остаётся отдельным и только для чтения.

Для внешней PostgreSQL вместо встроенной: создайте **копию** базы, проверьте и примените `sql/schema.sql` в копии, задайте `BIGFAMILY_SHARED=1`, `BIGFAMILY_OWNER_LOCAL=0`, `BIGFAMILY_PASSWORD` и `DATABASE_URL`. Работающая старая база не изменяется автоматически; новые таблицы `order_batches` и `write_receipts` добавляются этой схемой без удаления записей. Перед обновлением сохраните pg_dump/JSON. Для нескольких серверных процессов используйте внешнюю PostgreSQL.

Часовой пояс склада по умолчанию `Asia/Tashkent`, единый для браузера и сервера. При необходимости задайте `NEXT_PUBLIC_WAREHOUSE_TZ` **до сборки** и на сервере запуска. Даты операций хранятся как календарные дни, метки создания — как timestamps с часовым поясом.

## Проверки

```sh
npm run lint
npm run typecheck
npm run build
```

Для функциональных тестов запускайте **отдельный локальный тестовый сервер**, например под Linux/macOS:

```sh
BIGFAMILY_SHARED=0 BIGFAMILY_DATA_DIR=/tmp/bigfamily-test-db npm start -- -p 3181
```

В другом терминале: `python3 tests/smoke.py http://127.0.0.1:3181`. Для браузерных сценариев установите Chromium командой `npx playwright-core install chromium`, затем `npm run test:browser -- http://127.0.0.1:3181` (или укажите существующий исполняемый файл через `CHROMIUM_PATH`). Тесты создают свои изолированные ключи. Нельзя направлять их на рабочие данные.

Сведения об оригинале и выполненных проверках — в `RESTORATION.md`. Установочные зависимости зафиксированы `package-lock.json`. Шрифты Manrope и Unbounded входят в пакеты Fontsource; их открытые лицензии находятся в пакетах.

Дополнительные проверки: `python3 tests/orders.py http://127.0.0.1:3181` и `node tests/print-and-sync.mjs http://127.0.0.1:3181` (с теми же настройками Chromium). Проверяется сценарий 500 / 500 / 120 / 380, конкурентный повтор запроса, перенос старых копий, межвкладочное обновление и печать 121 варианта на нескольких листах.
